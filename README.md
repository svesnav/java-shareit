# ShareIt

Сервис для публикации вещей, бронирования и отзывов. Java 21, Spring Boot, Spring Data JPA и PostgreSQL.

## Запуск

На Windows можно подготовить и запустить локальный PostgreSQL из терминала PowerShell в папке проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-db.ps1
```

Скрипт требует Java 21, при первом запуске скачивает PostgreSQL, создаёт базу `shareit` и запускает сервер на `localhost:5432`.
База хранится в `.local-postgres` внутри проекта; эта папка исключена из Git. Повторный запуск сохраняет данные.
После перезагрузки компьютера выполните команду снова, затем запускайте `ShareItApp` в IDEA.
Если порт уже занят, скрипт проверит подключение с настройками проекта и не будет запускать второй сервер.

Если PostgreSQL уже установлен и вы хотите настроить его вручную, создайте базу:

```sql
CREATE DATABASE shareit;
```

По умолчанию приложение подключается к `jdbc:postgresql://localhost:5432/shareit` с пользователем и паролем `postgres`.
Для другой конфигурации задайте переменные окружения `DB_URL`, `DB_USERNAME` и `DB_PASSWORD`.

```shell
mvn spring-boot:run
```

Приложение доступно на порту 8080. Таблицы и индексы создаются из `src/main/resources/schema.sql`.
Повторный запуск сохраняет существующие данные. Hibernate проверяет соответствие схемы сущностям.
Таблица `requests` подготовлена для связи с вещами; REST-сценарии запросов вещей относятся к следующему спринту.

## Основные сценарии

- `/users` — создание, просмотр, изменение и удаление пользователей.
- `/items` — добавление, изменение, просмотр и поиск доступных вещей.
- `/bookings` — создание и просмотр бронирований пользователя.
- `/bookings/owner` — бронирования вещей владельца.
- `PATCH /bookings/{bookingId}?approved=true` — подтверждение; `approved=false` — отклонение.
- `POST /items/{itemId}/comment` — отзыв после завершённого подтверждённого бронирования.

Для запросов к вещам и бронированиям передавайте идентификатор пользователя в заголовке `X-Sharer-User-Id`.
Фильтры бронирований: `ALL`, `CURRENT`, `PAST`, `FUTURE`, `WAITING`, `REJECTED`. По умолчанию — `ALL`.
Даты передаются в формате ISO, например `2027-01-10T12:00:00`, без часового пояса.
При просмотре вещи отзывы видны всем пользователям, а последнее и ближайшее подтверждённые бронирования — владельцу.

## Проверки

```shell
mvn -Pcheck verify
```

Интеграционные тесты используют H2 в режиме совместимости с PostgreSQL и тот же `schema.sql`.
Проверяются CRUD, права доступа, даты и состояния бронирований, отзывы, ограничения БД и повторное создание схемы.
